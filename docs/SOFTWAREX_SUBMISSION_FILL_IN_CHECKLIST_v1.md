# SoftwareX Submission Fill-In Checklist v1

This checklist is the shortest path from the current manuscript drafts to a
real submission package. It is intentionally practical and should be completed
before final template conversion and public release.

Official guide checked on `2026-04-23`:

- Guide for authors:
  [https://www.sciencedirect.com/journal/softwarex/publish/guide-for-authors](https://www.sciencedirect.com/journal/softwarex/publish/guide-for-authors)
- Journal overview:
  [https://www.sciencedirect.com/journal/softwarex](https://www.sciencedirect.com/journal/softwarex)

## 1. Manuscript base decision

- [ ] Final short manuscript base confirmed as `docs/SOFTWAREX_MANUSCRIPT_v4.md`
- [ ] Official journal template format chosen: `Word` or `LaTeX`
- [ ] Final title confirmed
- [ ] Short title confirmed
- [ ] Abstract final copyedited
- [ ] Keyword list final checked

## 2. Author and title-page metadata

- [ ] Final author order confirmed
- [ ] All author names match the submission system spelling
- [ ] Full affiliation addresses prepared
- [ ] Country names included in affiliations
- [ ] Corresponding author confirmed
- [ ] Corresponding author email confirmed
- [ ] Corresponding author postal address confirmed
- [ ] Corresponding author phone number confirmed
- [ ] ORCID identifiers collected if to be included
- [ ] Present/permanent address notes added only if needed

## 3. Authorship and declarations

- [ ] CRediT roles assigned for every author
- [ ] Funding statement finalized
- [ ] Conflict-of-interest statement finalized
- [ ] Elsevier declarations tool completed for all authors if required by the submission system
- [ ] Generative-AI disclosure decision made
- [ ] If AI disclosure is needed, final statement inserted
- [ ] If AI disclosure is not needed, the section is removed from the manuscript

## 4. Data and software availability

- [ ] Final public GitHub repository URL prepared
- [ ] Public release/tag selected for submission
- [ ] Release notes prepared
- [ ] Data statement aligned with the public repository and release archive
- [ ] Software availability section updated with repository URL
- [ ] Software availability section updated with release identifier
- [ ] Permanent identifier added if a DOI or archival record is available

## 5. Repository readiness

- [ ] Repository is public
- [ ] `README.md` is final enough for public inspection
- [ ] `LICENSE` is final and visible
- [ ] Citation metadata is present and correct
- [ ] Public release/tag created
- [ ] Source tree remains clear and reviewable
- [ ] If desired, external CI status is visible for extra release confidence

## 6. Optional but recommended extras

- [ ] Highlights retained for submission
- [ ] Highlights file copyedited one final time
- [ ] Decision made on graphical abstract
- [ ] If yes, graphical abstract image exported in a journal-acceptable format

## 7. Final file set

- [ ] Official-template manuscript
- [ ] Highlights file, if included
- [ ] Graphical abstract, if included
- [ ] Cover letter
- [ ] Final repository URL
- [ ] Final release/tag identifier

## 8. Submission-system sanity check

- [ ] Word-count sanity check completed against the official counting rule
- [ ] Figures embedded correctly if submitting the Word template
- [ ] References reviewed for software/release citations
- [ ] Acknowledgements section remains directly before the reference list
- [ ] All placeholders removed
- [ ] Submission package reread once end-to-end before upload
